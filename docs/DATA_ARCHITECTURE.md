# Beautiful AI Prompt — Static Content & Data Architecture

## Overview

In **Phase 1**, BeautifulAIPrompt.com runs on an entirely static, strongly typed in-memory data architecture. No database, server runtime, or external network calls are required.

To ensure long-term scalability and seamless migration to PostgreSQL / Supabase / Prisma in **Phase 2**, the architecture implements the **Repository Pattern** with 1:1 relational mappings.

## Domain Models

### 1. `Prompt` Type ([`src/types/prompt.ts`](file:///Users/ramannagar/Desktop/project/beautiful_ai_prompt/src/types/prompt.ts))
Contains all required fields for search, filtering, and model compatibility:

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique identifier (e.g. `'p-career-001'`) |
| `slug` | `string` | URL-safe slug (e.g. `'career-transition-roadmap-architect'`) |
| `title` | `string` | Descriptive title |
| `shortDescription` | `string` | Brief overview for preview cards |
| `description` | `string` | In-depth role & execution context |
| `category` | `string` | Primary category ID matching `Category.id` |
| `subcategory` | `string?` | Optional subcategory grouping |
| `tags` | `string[]` | Keyword search tags |
| `prompt` | `string` | Raw prompt template with bracketed placeholders `[var_name]` |
| `variables` | `PromptVariable[]` | Interactive customizable parameters |
| `exampleInput` | `Record<string, string>` | Sample arguments used for QA benchmarking |
| `exampleOutput` | `string` | Realistic output generated by AI model |
| `useCases` | `string[]` | Bullet points of target real-world scenarios |
| `difficulty` | `'beginner' \| 'intermediate' \| 'advanced'` | Complexity level |
| `compatibleModels` | `AIModelId[]` | Supported AI engines |
| `featured` | `boolean` | Display in hero / highlights |
| `trending` | `boolean` | Display in trending feeds |
| `relatedPromptIds` | `string[]` | Cross-referenced prompts in related workflows |
| `createdAt` | `string` | ISO 8601 timestamp |
| `updatedAt` | `string` | ISO 8601 timestamp |

### 2. `PromptVariable` Type
Supports interactive variable substitution:
- `name`: Technical key matching template token `[name]` or `{{name}}`
- `label`: Human-readable input label
- `description`: Helper tooltip or subtext
- `placeholder`: Input placeholder
- `required`: Boolean validation flag
- `type`: `'text' | 'textarea' | 'select'`
- `options`: String array for `select` type
- `defaultValue`: Pre-filled initial value

## Repository Layer (`src/lib/data/`)

UI components **never import raw JSON or array arrays directly**. All access occurs through repository functions:

```tsx
import { getAllPrompts, getPromptBySlug, filterPrompts } from "@/lib/data/prompts";
import { getAllCategories, getCategoryBySlug } from "@/lib/data/categories";
```

### Why This Matters for Phase 2 Migration:
When moving to PostgreSQL / Prisma / Supabase in Phase 2:
1. Only the implementations inside `src/lib/data/*.ts` change (from `return PROMPTS.filter(...)` to `return await db.prompt.findMany(...)`).
2. **0 React components or routes require modifications**.
3. All UI cards, search modals, and page layouts stay identical.

## PostgreSQL Migration Architecture

See [`docs/POSTGRESQL_MIGRATION_SCHEMA.sql`](file:///Users/ramannagar/Desktop/project/beautiful_ai_prompt/docs/POSTGRESQL_MIGRATION_SCHEMA.sql) for the exact DDL.

### Entity Relationship Mapping:

```
[ai_models]
    id (PK)

[categories]
    id (PK) <────────┐ (FK category_id)
                     │
                 [prompts] ──────────────┐ (FK prompt_id)
                     id (PK)             │
                     variables (JSONB)   │
                     example_input(JSONB)│
                                         ▼
                               [collection_prompts] (Join Table)
                                         ▲
                                         │ (FK collection_id)
                               [collections]
                                   id (PK)
```

### Seeding PostgreSQL:
When Phase 2 begins, the static dataset can be imported using a straightforward seed script:

```ts
import { PROMPTS, CATEGORIES, COLLECTIONS, AI_MODELS } from "@/data";
import { db } from "@/lib/db";

async function seed() {
  await db.aiModel.createMany({ data: AI_MODELS });
  await db.category.createMany({ data: CATEGORIES });
  await db.prompt.createMany({ data: PROMPTS });
}
```
